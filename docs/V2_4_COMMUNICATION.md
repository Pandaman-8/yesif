# V2.4 communication and selected-plan clarity

Short drafts now express the condition, the proposed change and the agreement request, normally in two or three sentences. Task names, dates and reduced hours come from inputs; `simulate` verifies a chosen option again. No draft implies automatic approval or invents a deliverable.

- Fits: confirm the original scope/priority under current estimates, without inventing conflict.
- Deferral: identify each moved obligation, require agreement to move beyond this week, and ask for replacement deadlines after checking future capacity.
- Scope: explicitly offer a smaller result at the selected hours. Include the user's exact description if entered. Otherwise state that the deliverable still needs definition. No arbitrary minimum replaces quarter-hour mathematics.
- Combined: retain BOTH deferral and scope agreement.
- Unresolved: lead with actual due work, usable time and shortfall at the first violated date; distinguish preexisting conflict. Ask to discuss relevant deadline/time conditions and recheck every deadline before confirming the request.

The message is separate from a structured evidence disclosure. Feasible evidence lists the selected change, assigned/effective hours, all five deadline checks, required agreement and model limits. Blocked evidence lists the first violation, existing-only comparison, actual contributors, causal attribution, later failed checks and the all-week recheck requirement. It is not a second email.

The adjacent selected-plan summary describes one option only: full or reduced request, original versus selected effort, moved hours still owed, original deadlines needing replacement, retained commitments, unassigned capacity and unchecked future capacity. It recomputes totals rather than trusting a cached result. No comparison workspace or preference ranking was added.

## Editor and persistence

The reduced-deliverable input is available directly on Proposal for recommended, manual and combined reductions. Its existing 500-character field uses the existing draft/notebook schema. Typing updates only the scope description and dirty state. An explicit “Update generated draft with this scope” button uses the established reset/save/discard/cancel flow. It never silently replaces manual text. The calculation's evidence and the editor are explicitly independent; no arbitrary edited sentence is labelled verified.

Changing the selected plan still uses App's existing guarded recalculation and generation flow. Practice never writes to storage. Existing saved messages, notes, outcomes and drafts are read without migration or regeneration. Full-scope proposals do not expose the smaller-result field. A description does not prove the reduced estimate is practically sufficient; contents and estimate must be agreed together.
